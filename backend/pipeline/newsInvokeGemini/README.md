# newsInvokeGemini

The topic selector at the head of the content pipeline. Despite the name, it does not call Gemini. It fetches 26 hard-coded RSS feeds (BBC, Al Jazeera, Guardian, AllAfrica, CNA and others) and sends them to one LLM call that picks up to `TOPICS_LIMIT` topics (default 15, max 20). Order of a run: fetch, **raw capture** (every fetched item to the inbox), collapse same-event items, model, drop repeats, write. The prompt asks for events of three kinds (a start, a move in a story we follow, a measured change), carries the done-not-said rule (decision 0020) and a significance floor instead of a quota, and lists the stories we follow (today plus 14 days, below). It drops source URLs that were not among the fetched articles, enriches sources (`src/source_enrichment.js`, `src/_shared/outlets.js`), and writes the topics cache item with `status: 'pending'`. It also writes a saw-vs-chose capture to S3, read by newsSelectionShadow and `predictions/jev-backtest` (the audit that once read it was removed 2026-11-01).

## Reads / writes
- DynamoDB `TOPICS_DDB_TABLE` (key `id`): reads `seen-today` and `archive#YYYY-MM-DD` (today and the previous 14 days: title, `threadId`, `archivedAt` of each entry); writes the cache item `id = TOPICS_CACHE_ITEM_ID` (default `staging`) and `seen-today`.
- S3 `WORLD_BUCKET`: appends **every fetched item** to `record/inbox/articles/YYYY-MM-DD.jsonl` (raw capture, below; shadow `record/shadow/inbox/articles/` when `RAW_CAPTURE_SHADOW=1`). Also writes `audit/ingest-capture/latest.json` plus `audit/ingest-capture/YYYY-MM-DD/HHMM.json` (`INGEST_CAPTURE_PREFIX`). Fenced: a failure never breaks ingestion.
- External: the RSS feed hosts listed in `src/selection.js` (`RSS_FEEDS`), and the LLM endpoint below.
- Env: `WORLD_BUCKET`, `RAW_CAPTURE_SHADOW`, `SOURCE_ENRICH_ENABLED`, `SOURCE_ENRICH_THRESHOLD`, `SOURCE_ENRICH_MAX`, `SOURCE_ENRICH_CROSS_TOPIC`, `TOPICS_LIMIT`.

## Gotchas
- Model-reply checks (whole or salvaged from a truncated reply): source URLs match the fetched pool after one HTML-entity decode and a trim (`&amp;` vs `&`); category `diplomacy` is mapped to `politics`, any other unlisted category is dropped; after the repeat drop, only the first `limit` topics are kept. Test: `test/topicFilters.test.js`.
- A failed run on a scheduled event (missing key, model/upstream error, empty reply) throws, so the Lambda `Errors` metric counts it; only direct HTTP invocations get a 4xx/5xx response body. Test: `node --test src/scheduled-failure.test.js`.
- The names "Gemini" and "Grok" in the code, logs and env names are historical.
- It emits `Access-Control-Allow-Origin: *` on its HTTP-shaped responses. If a Function URL is ever added, its CORS config must stay empty.
- `max_tokens` is 16000; truncated JSON output goes through `salvageTruncatedTopics`.

## Source field contract

Source fields are bound to the fetched RSS URL: `publishedAt` is ISO UTC (null when missing or invalid), while `age` stays for older readers. `outlet` comes only from `src/_shared/outlets.js` (`getOutletMeta`); unknown domains keep null. Country codes pass the shared `resolveIso3` resolver; unknown inputs are dropped and logged with their count.

Offline source-field regressions: `node --test src/source-fields.test.js` (from this folder).

## Raw capture (inbox)

Before any model call the run appends every fetched item (the url-deduped pool, not the collapsed prompt rows) to `record/inbox/articles/YYYY-MM-DD.jsonl`, so a model outage never loses the day (decision 0040). The selector is the only writer of that prefix; the facts writer turns lines into facts later. Line: `{schemaVersion:1, rawId, url, canonicalUrl, title, outlet, feed, publishedAt|null, fetchedAt, snippet|null, lang|null}`; `rawId = sha1(canonicalUrl)` (`_shared/record.js`), so an item seen again by a later run is skipped and the first line stays. Day = UTC day of `publishedAt`, else of `fetchedAt`. Each day file is read-modify-written with `appendLines` (conditional write, retried on a lost race); a run touches up to three day files (48 h window). A failed or slow (30 s) write is logged `[raw-capture] failed (non-fatal ...)` and the run continues.

## Selection rules in code

- Parser (`parseRssXml`): `<item ...attributes>` (Dawn `xmlns:`, DW and Nikkei `rdf:about`), Atom `<entry>` with `<link href>`, `<dc:date>`/`published`/`updated` as the date, `description`/`summary`/`content` as the snippet, HTML entities decoded (Dawn and CNA escape their HTML). A bare `<item>` pattern would drop Dawn, DW and Nikkei Asia. Nikkei's feed has no date and no description.
- Prompt (`buildSelectionPrompt`, rules in `selectionRules`): the model is the editor of a record of stories and picks events of three kinds: **A** a start (opens a story more will come of), **B** a move (something done in a story we follow, `follows` = its number), **C** a measured change (an official figure or a major study whose change is large by the source's own account, or that feeds a followed story; `event_type: "measure"`). A one-off that connects to nothing is left out (a single crime or a criminal case against a private person, though not one against an office-holder or political figure; a minor accident; a one-day stunt; a celebrity or entertainment announcement; one expert's opinion: examples from the 2026-11-18 replay), but rule 5 wins: an event that clears the floor always gets in. Rules 1 to 5 (decision 0062 draft, commit 006775fc): one event per topic; title only what the articles state; sources from the list, every reporting article; done, not said (a reaction in a followed story is not a move either); the significance floor (10 deaths or 100 injured or displaced; head of state or government or parliament decision; nationally significant court ruling; treaty, sanction, expulsion, recognition; strike or attack on infrastructure; disaster declaration), the limit as a hard cap, the list written in order of significance with every floor event first (so a long list loses only its least significant event; the replay saw 14 or 15 topics in 9 of 14 runs), fewer is correct. Rule 6: name a followed story only by its number, only when plainly part of it, and the one with the most entries when several cover the same situation, even when another story's newest title matches better. Regional diversity is a soft note.
- Stories we follow (`followedStories(entries, nowMs)`, shared with `backend/record/cli/recover-late-lib.mjs`): one line per `threadId` in the archive entries of today and the 14 days before, `S12 · 2026-11-17 · 4 · <newest title> (began: <oldest title>)` (run-local number, last entry date, entries in the window, newest entry's title; for 2 or more entries the oldest title in the window, left out when it is the same text, so an event that matches how the story began still finds it). Stories with 2 or more entries first, then single-entry ones, newest first in each group; cap 350, so the oldest single-entry stories are cut first; log `FOLLOWED: n stories listed, m cut`. An entry without a `threadId` is not listed. An archive day that cannot be read is left out and logged; the run goes on, at worst with `(none)` (decision 0057). The seen-today list is no longer in the prompt; it stays in code for the repeat drop.
- Answer field `follows` (optional): a listed number sets `continues_thread` (the story's thread id) and `continues_topic` (its listed title) on the topic in `staging`, where the agent's threading (`threading.joinRun` over the raw staging topics) reads them. An unknown number is dropped and logged `FOLLOWS: unknown "S99"`. The model no longer writes `continues_topic` itself; a value it sends is ignored. `event_type` is one of war, unrest, diplomacy, election, policy, economy, markets, disaster, health, tech, measure, other; anything else becomes `other`.
- Dedupe (`src/dedupe.js`): before the model, items with the same canonical url or title token Jaccard >= 0.6 collapse to one prompt row (the longer description stays; the full pool is still used to validate and enrich sources). After the model, a topic that repeats a title of the last 24 h runs or of today or yesterday's archive (Jaccard >= 0.5) is dropped unless its title has a number the earlier title lacks; a move is not exempt, and the drop log line names its story (`[follows S12]`).

## Choices

- Raw capture stores the whole fetched pool, not the collapsed prompt rows: the raw layer loses nothing, the collapse is a prompt economy.
- Collapse uses the 0.6 Jaccard from the brief; the post-model drop uses 0.5 (the audit's method) because topic titles are model-written paraphrases. Both ignore a short stop-word list and thousands separators.
- The post-model check reads `seen-today` (24 h) plus archive rows dated yesterday or today, so a topic from an earlier run today is caught before the analysis agent has archived it.
- Known wart: entity decoding applies to titles and snippets, not to `url`. BBC links keep a literal `&amp;` as fetched, so their canonical urls contain `amp;at_campaign`; kept on purpose so entry ids (sha1 of the canonical url) do not change across the deploy.
- Fetch cap vs prompt pool (decision 0040 answer 2): `FEED_FETCH_CAP = 25` items per feed are fetched and captured; after collapse, `PROMPT_POOL_PER_FEED = 8` (newest by publishedAt, undated last) per feed go to the model. The full fetched pool still serves source validation and enrichment.
- The inbox write uses `WORLD_BUCKET`, falling back to the bucket name hard-coded for `audit/ingest-capture`.
