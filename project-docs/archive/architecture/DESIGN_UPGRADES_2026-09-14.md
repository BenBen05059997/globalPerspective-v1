# Design Upgrades — industry patterns pressure-tested against this codebase

_2026-09-14. Status: **decision record — nothing here is built yet.** Six industry-standard patterns
("how other people run systems shaped like ours") were proposed, then pressure-tested by two
independent code-grounded passes for what each would actually touch and cost HERE (solo dev, CI-free
by design, manual zip-patch deploys, no IaC). This doc records the verdicts and the resulting
adopt-list. Companion terrain docs: `WORLD_MODEL_FRAGMENTS.md` (merge/serial/distinct map),
`SCORING_STANDARDS.md` (rubric/benchmark audit), and the 3-way optimization debate summarized in §4._

## §1 The headline

The system's shape — small timer-driven Lambdas communicating through DynamoDB/S3, materialized
views served read-only — is a legitimate, known-good pattern (**choreographed serverless ETL**).
The pressure-tests confirmed the gap is not the architecture; it's the *supporting practices*
mature teams wrap around this shape. And strikingly, **every adopted item below is a read-only
script or monitor — verification machinery, not architecture surgery.** The two heavyweight
rewirings (event-chains, bundlers) both failed the pressure-test on this shop's constraints.

## §2 Verdict table

| # | Pattern (what others do) | Verdict | Adopted form |
|---|---|---|---|
| 1 | Event-chain instead of clock-chain (Airflow/Dagster/Step Functions dependency triggering) | **SKIP** (revisit on first observed stale-feed incident) | **Completion-marker guard**: downstream reads upstream's output timestamp, logs a loud warning when consuming stale data. | 2 | Fleet manifest + reconciler (service-catalog / IaC-state lite) | **ADOPT-NOW (scoped)** | `scripts/reconcile-fleet.mjs` — SDK-based read-only diff of live AWS vs repo, modeled on `newsModelGuard`'s existing ListFunctions pattern. Manifest auto-generated from live reads, not hand-maintained. |
| 3 | Central model config (`models.json`) | **SKIP** | **Code-default scan**: a repo-grep script closing `newsModelGuard`'s blind spot (it reads env vars, never the hardcoded fallbacks in ~19 Lambdas). Zero redeploys. |
| 4 | Data contracts + freshness SLOs (dbt/Dagster asset checks) | **SPLIT** | Freshness half **ADOPT-NOW**: generalize `newsFreshnessMonitor` into one table-driven checker over ~8-12 stitched artifacts (zero touch to existing Lambdas). ## §3 Key pressure-test findings (the reasons behind the verdicts)

**Event-chain (skipped).** Of ~8 adjacent cron pairs, only 4 are true reader/writer dependencies
(thread→country, thread→systems, thread→econ, econ→econQuality); one (thread+country→drift) is
already self-healing via a 10-day lookback; country→systems is coincidental timing only. Rewiring
would introduce a class with zero fleet precedent (no Lambda uses EventBridge PutEvents today),
manual IAM per function, and trades the current *silent-stale* failure mode for *silent-skip* —
arguably worse in a shop with nothing watching for a skipped stage. The completion-marker guard
gets the "never silently consume stale data" benefit at a fraction of the cost.

**Reconciler (adopted).** The bare-single-`aws`-command permission convention does NOT block it:
a Node script using the AWS SDK sidesteps the CLI allowlist entirely, and `newsModelGuard/src/index.js:50-59`
is a working in-repo template (paginated ListFunctions + env reads). It retires whole failure
classes this repo has actually hit: repo≠deployed (`newsAnalyze`), dead env vars, orphaned
schedules, `DRY_RUN` ambiguity. Proof it's needed arrived during the test itself: **`ARCHITECTURE.md`
§10 still described `linkedInAutoPost` as live** three days after its full retirement (fixed
2026-09-14, same commit as this doc). Hand-maintaining a manifest is the known risk — so the
manifest is generated by the script, never hand-edited.

**Bundler (skipped) — with one important correction.** The two byte-identical pairs
(`riskDimensions.js`, `situations-core.js`) are the only true bundler candidates. `sendEmail.js`,
previously cited as "drift proof," is actually a **documented deliberate fork** — the
`newsEmailSender` copy's header says "Copied … and EXTENDED" (List-Unsubscribe headers). So the
codebase has *one* cosmetic near-miss (a sync comment not copied back) and *zero* functional
accidental-drift incidents. That doesn't justify build tooling; it justifies a diff gate. The
Firebase-JWT block spans ~6 files in non-identical shapes — verify before extracting, don't
assume one clean module.

**Freshness (adopted), contracts (deferred).** None of the ~10 stitched artifacts
(`world/latest.json`, `stories/index.json`, `threads/story-map.json`, `situations/inbox/…`,
`signals/latest.json`, `predictions/track_record.json`, `audit/…`, `corpus/…`, DDB `staging`/`latest`)
has any schema check at either end — consumers use defensive `(m && m.pairs) || {}`. But every
documented incident in this repo's history is model-retirement or token-ceiling shaped, never
shape-drift. So: build the cheap generic freshness checker now (a 1-for-1 generalization of the
proven `newsFreshnessMonitor` pattern; a standalone reader touching zero existing Lambdas), and
hold JSON-schema validation until a shape incident actually occurs. Watch double-paging: the
situation tracker already has its own CloudWatch alarms — the generic checker must not duplicate them.

**Model config (skip S3, adopt the scan).** 19 Lambdas carry a `*MODEL*` env var AND an independent
hardcoded fallback literal — a second copy of the model choice `newsModelGuard` cannot see. The S3
`models.json` fix would require a one-time redeploy of ~20-30 Lambdas in a manual zip-patch shop —
the single most expensive move of all six patterns — for a gap that a zero-redeploy repo-grep script
closes at the detection level. The proven fix-on-alert loop (2026-07-24 incident → modelGuard →
clean since) covers the rest.

**Codebook (adopted — highest leverage).** The severity tier's entire calibration text is one
sentence ("0-24 = low, 25-49 = moderate, 50-74 = elevated, 75-100 = severe") applied identically to
two structurally different judgments (country posture vs thread severity), with zero ground truth —
while ACLED/GDELT/ICEWS, the actual field this product operates in, treat a codebook + gold sample +
agreement statistics as mandatory. Everything needed fits existing `quality/` conventions:
`golden_evals.json`'s fixture shape (whose own `_meta` disclaims LLM-quality scope — the gold set is
the missing "Layer 2"), `pick_weekly_review.js`'s sample-then-hand-review workflow for labeling, and
`calibration_report.js`'s dated-markdown output style. Cost: ~half-day engineering + 1.5-2.5
operator-hours to label 25 events. **Hard sequencing rule: baseline-score the CURRENT thin rubric
against the gold set BEFORE changing any prompt language** (the `trackRecord.js`
methodology-version/era-cut precedent) — otherwise rubric-vs-model attribution is lost forever.
Budget for a rolling/cumulative gold set: 25 events × sparse axes = thin per-axis samples.

## §4 How this composes with the optimization debate (2026-09-14)

A 3-way adversarial debate (Consolidator / Subtractor / Reliability-pragmatist) preceded this
pressure-test. Its convergent results, updated by the tests:

- **Unanimous, still valid:** delete the truly-dead surface (Stripe/Paddle dir, dev.to dead path,
  orphaned env vars); no Lambda layers ever.
- **Corrected by the pressure-test:** the "kill `linkedInAutoPost` schedule" top move was ALREADY
  DONE 2026-09-11 (the earlier "may still be firing" claim was stale; live scheduler listing shows
  only `InvokeDev` + `InvokeLinkedIn`). The residue was the ARCHITECTURE.md §10 doc drift, now fixed.
  And `sendEmail.js` "drift" was a deliberate documented fork (§3), weakening the consolidation-urgency
  claim — reconcile it only if breaking-alert emails ever go to subscribers (they'd then need the
  unsubscribe headers).
- **The debate's `cp`-discipline + sync-checker mechanism won** over both layers and bundlers once
  pressure-tested; the Reliability position's "verify before refactor" sequencing is effectively
  what §2's adopt-list implements.

## §5 The resulting build-list (all small; none started)

1. `scripts/check-shared-sync.mjs` — diff gate for the shared byte-identical pairs. (Smallest.)
2. `scripts/audit-model-defaults.mjs` — hardcoded-model-fallback scan closing modelGuard's blind spot.
3. `scripts/reconcile-fleet.mjs` — SDK-based live-AWS-vs-repo reconciler (auto-generated manifest).
4. Generic artifact-freshness checker (new small Lambda or extension, table-driven, ~8-12 artifacts).
5. Completion-marker staleness guard on the 4 true daily-chain dependencies.
6. Severity codebook + 25-event gold set + agreement script (with the baseline-first sequencing rule).

Ordering rationale: 1-3 are pure read-only scripts (zero deploy risk), 4-5 touch runtime lightly,
6 is the highest-leverage but needs operator labeling time. None requires CI, new infra classes,
or a fleet redeploy — that constraint is what eliminated the three skipped patterns.
